# Диалект Turbo Pascal 3.0: спецификация для Pesto/11

Документ описывает язык, который принимает Pesto/11: диалект Turbo Pascal 3.0 (далее TP3) и отклонения от него.

**Источник.** *TURBO Pascal Reference Manual, Version 3.0*, CP/M-80 edition (перенабор Alpha Systems, Dec 1988). Ссылки вида «§9.4» указывают на разделы этого руководства, «прил. I» — на приложения. Руководство защищено авторским правом. Здесь записаны только факты (грамматика, семантика, коды ошибок) своими словами. Текст руководства сюда не копируется.

Грамматика из приложения I в руководстве неполна и местами неточна (например, `else` в `if` записан как повторяемый элемент). Ниже она переписана и сверена с текстом глав.

Пометки в документе:
- **[P11]** — решение или отклонение Pesto/11 от TP3;
- **[?]** — вопрос, который нужно проверить на настоящем TP3.

## 1. Лексика

### 1.1. Символы и регистр (§2.1)

- Буквы: `A`..`Z`, `a`..`z`, `_`. Цифры: `0`..`9`.
- Регистр букв не различается ни в ключевых словах, ни в идентификаторах.
- Двухсимвольные лексемы: `:=` `<>` `<=` `>=` `..` `(*` `*)`.
- Альтернативные скобки: `(.` и `.)` вместо `[` и `]`.
- Специальные символы: `+ - * / = < > ( ) [ ] { } . , : ; ' # $ ^`.
- В TP3 значимы только первые 127 символов строки исходника (§2.5). **[P11]** Ограничения на длину строки нет.
- **[P11]** Исходник читается в КОИ-8Р. Символы с кодами 128–255 допустимы только внутри строк и комментариев.
- **[P11]** Концы строк: CR/LF (Windows, RT-11), LF (Linux, macOS) или одиночный CR (старый Mac OS). В одном файле они могут быть перемешаны. Символ `^Z` (код 26) считается концом файла, как в текстовых файлах CP/M и RT-11. Всё, что идёт после него, игнорируется. Это относится и к include-файлам: `^Z` заканчивает только текущий файл.

### 1.2. Зарезервированные слова (§2.2)

```
absolute  and       array     begin     case      const     div       do
downto    else      end       external  file      for       forward   function
goto      if        in        inline    label     mod       nil       not
of        or        overlay   packed    procedure program   record    repeat
set       shl       shr       string    then      to        type      until
var       while     with      xor
```

Сверх стандартного Pascal добавлены: `absolute`, `external`, `inline`, `overlay`, `shl`, `shr`, `string`, `xor`. Слово `forward` в руководстве отмечено как зарезервированное.

### 1.3. Идентификаторы (§4.1)

Начинается с буквы или `_`, дальше буквы, цифры и `_`. Значимы все символы.

В TP3 длина идентификатора ограничена только длиной строки исходника (127 символов), поэтому на практике максимум — 127 символов.

**[P11]** Максимальная длина идентификатора — 127 символов, для совместимости с TP3. Хотя длина строки исходника не ограничена, более длинный идентификатор — ошибка компиляции.

### 1.4. Числа (§4.2)

- Целые: десятичные `-32768..32767` или шестнадцатеричные `$0000..$FFFF` (знак `$`, затем hex-цифры).
- Вещественные: `цифры.цифры`, `цифры.цифры E порядок`, `цифры E порядок`. Порядок может иметь знак.
- Целое число допустимо везде, где ожидается вещественное.
- Целая константа вне диапазона Integer — ошибка 56. Большие целые значения нужно записывать как вещественные (`123456789.0`).
- **[P11]** Вещественные константы переводятся в DEC F (4 байта) и теряют точность после 7-го знака.

### 1.5. Строки и управляющие символы (§4.3)

- Строковая константа в одинарных кавычках. Кавычка внутри строки записывается удвоенной: `''`.
- Строка из одного символа имеет тип Char.
- Пустая строка `''` совместима только со строковыми типами.
- Управляющие символы записываются двумя способами:
  - `#n`, где `n` — целая константа 0..255, десятичная или `$hex`;
  - `^X` — управляющий символ. Для букв и `[ \ ] ^ _` код равен `Ord(UpCase(X)) xor $40`: `^G` = `^g` = 7, `^[` = 27.
- Кавычечные строки и управляющие символы склеиваются в одну строку, если идут подряд без разделителей: `#27'Y'`, `'Text'^M^J`, `#13#10`.
- Одиночный `^G` имеет тип Char, склеенная строка вроде `'A'^G` — тип String.
- **`^X` нельзя распознать лексически.** `const c = ^G;` — это символ, а `type t = ^G;` — указатель на тип `G`, хотя оба начинаются одинаково. Значение `^` определяет парсер по месту в грамматике:

  | Место | Значение `^` |
  |---|---|
  | начало множителя в выражении | управляющий символ |
  | константа (`const`, метка `case`, вариант записи, элемент множества-константы) | управляющий символ |
  | продолжение строкового литерала (`'AB'^C'DE'`) | управляющий символ |
  | начало описания типа (`^Integer`) | тип-указатель |
  | после переменной (`p^`, `a[i]^.x`) | разыменование |

- **[?]** Как TP3 обрабатывает `^X`, когда `X` не буква: `^1`, `^` перед пробелом. По формуле `xor $40` получается `^1` = `'q'`, по формуле `and $1F` — `#17`. Допустимые символы после `^` тоже проверить.
- Строка не может переходить на следующую строку исходника (ошибка 55).

### 1.6. Комментарии (§4.4)

- `{ ... }` и `(* ... *)`.
- Однотипные комментарии не вкладываются. Разнотипные вкладываются: `{ ... (* ... *) ... }` и наоборот.

### 1.7. Директивы компилятора (§4.5, прил. C)

- Директива — это комментарий, у которого сразу после `{` или `(*` стоит `$`. Пробелы вокруг `$` не допускаются.
- Внутри перечисляются буквы с `+`/`-` через запятую: `{$R+,V-}`.
- Отдельный вид — включение файла: `{$I имя}`. Подробнее в разделе 9.

## 2. Грамматика

Нотация:
- `::=` — определение;
- `|` — альтернатива;
- `[ ]` — необязательная часть;
- `{ }` — повторение ноль или более раз;
- `( )` — группировка;
- терминалы в кавычках.

Ключевые слова не зависят от регистра.

### 2.1. Программа и блок

```
program            ::= [ program-heading ] block "."
program-heading    ::= "program" identifier [ "(" identifier-list ")" ] ";"
block              ::= declaration-part compound-statement
declaration-part   ::= { label-part | const-part | type-part | var-part | subprogram-decl }
```

- Заголовок программы необязателен, список параметров в нём ни на что не влияет (§5.1).
- Разделы описаний могут идти **в любом порядке и повторяться** (§5.2).
- Всё нужно описать до первого использования. Исключение — тип в описании указателя (раздел 2.3).

### 2.2. Описания

```
label-part         ::= "label" label { "," label } ";"
label              ::= identifier | digit-sequence

const-part         ::= "const" const-def { const-def }
const-def          ::= identifier "=" constant ";"
                     | identifier ":" type "=" typed-constant ";"

type-part          ::= "type" type-def { type-def }
type-def           ::= identifier "=" type ";"

var-part           ::= "var" var-decl { var-decl }
var-decl           ::= identifier-list ":" type ";"
                     | identifier ":" type "absolute" ( constant | variable-identifier ) ";"

constant           ::= [ "+" | "-" ] ( unsigned-number | constant-identifier )
                     | string-literal
string-literal     ::= string-part { string-part }        (части без разделителей)
string-part        ::= quoted-string | "#" unsigned-integer | "^" char

typed-constant     ::= constant
                     | "(" typed-constant { "," typed-constant } ")"          (массив)
                     | "(" field-constant { ";" field-constant } ")"          (запись)
                     | "[" [ set-const-element { "," set-const-element } ] "]"  (множество)
field-constant     ::= field-identifier ":" typed-constant
set-const-element  ::= constant [ ".." constant ]
```

- В TP3 3.0 константа — это **не выражение**: число, имя константы (обе формы со знаком) или строка. Выражения вроде `N*2` в `const` и в границах типов появились только в TP4.
- `quoted-string` и `#n` склеивает токенизатор, `^X` — парсер (§1.5).
- Массив и запись в `typed-constant` различаются по второй лексеме после `(`: `идентификатор :` означает запись. Парсер выдаёт общее дерево «список элементов с необязательными именами полей», а с типом его сопоставляет валидатор.

- Метки могут быть идентификаторами или числами. Число может быть любым, не только до 4 цифр (§5.2.1).
- `absolute` применяется только к одному идентификатору (ошибка 75). Внутри записи `absolute` запрещён. Адрес задаётся целой константой или именем переменной или параметра (§22.7).
- Тип типизированной константы в руководстве описан как идентификатор типа. Но примеры в §13 используют и запись типа целиком (`set of Char`, `array[0..9] of Char`), поэтому здесь допускается `type`.

### 2.3. Типы

```
type               ::= simple-type | structured-type | pointer-type
simple-type        ::= type-identifier | enum-type | subrange-type
enum-type          ::= "(" identifier-list ")"
subrange-type      ::= constant ".." constant
pointer-type       ::= "^" type-identifier

structured-type    ::= [ "packed" ] ( array-type | record-type | set-type | file-type | string-type )
array-type         ::= "array" "[" simple-type { "," simple-type } "]" "of" type
string-type        ::= "string" "[" constant "]"
set-type           ::= "set" "of" simple-type
file-type          ::= "file" [ "of" type ]
record-type        ::= "record" field-list "end"
field-list         ::= [ fixed-part [ ";" variant-part ] | variant-part ] [ ";" ]
fixed-part         ::= record-section { ";" record-section }
record-section     ::= identifier-list ":" type
variant-part       ::= "case" [ identifier ":" ] type-identifier "of" variant { ";" variant }
variant            ::= [ case-label-list ":" "(" field-list ")" ]
```

- Тип, начинающийся с идентификатора: если следующая лексема `..`, это поддиапазон (`A..B`), иначе — имя типа. Тип, начинающийся с `(`, — перечисление. С `^` — указатель (в начале типа `^` всегда указатель, §1.5).
- `packed` допускается, но ничего не меняет (прил. D.6).
- `file` без `of` — нетипизированный файл. `Text` — стандартный идентификатор текстового файла.
- Индекс массива: любой простой тип, кроме Real. Запись `array[A, B] of T` равносильна `array[A] of array[B] of T` (§10.2).
- Длина строки — целая константа 1..255 (ошибка 49). Длины по умолчанию нет: `string` без `[n]` недопустим как тип.
- Базовый тип множества: перечисление, где не больше 256 значений, или поддиапазон с границами в 0..255 (ошибка 70).
- Файл не может быть компонентом файла (ошибка 68).
- В указателе `^T` тип `T` можно описать позже в том же разделе `type`. Если он так и не описан, ошибка 42.
- В вариантной части скобки вокруг списка полей обязательны, даже пустые. Поле-тег необязательно; без него получается «свободное объединение» (§11.3).

### 2.4. Подпрограммы

```
subprogram-decl    ::= procedure-heading ( block | "forward" | "external" constant ) ";"
                     | function-heading  ( block | "forward" | "external" constant ) ";"
                     | "overlay" ( procedure-heading block | function-heading block ) ";"
procedure-heading  ::= "procedure" identifier [ formal-parameters ] ";"
function-heading   ::= "function" identifier [ formal-parameters ] [ ":" type-identifier ] ";"
formal-parameters  ::= "(" param-section { ";" param-section } ")"
param-section      ::= identifier-list ":" type-identifier
                     | "var" identifier-list [ ":" type-identifier ]
```

- Тип формального параметра — **только идентификатор типа**: `array[1..10] of X` в заголовке недопустим (§16.1). То же относится к типу результата функции (§16.3.1).
- `var` без типа — нетипизированный параметр по ссылке (§16.1.2).
- Тело подпрограммы, объявленной через `forward`, начинается с сокращённого заголовка: `procedure Имя;` или `function Имя;`, без параметров и типа результата (§16.4). Поэтому тип результата в грамматике необязателен. Обязателен ли он, проверяет валидатор: без типа допустим только заголовок тела `forward`-функции.
- **[P11]** `overlay` не поддерживается: ошибка «not supported».
- **[P11]** Для `external` адрес задаётся целой константой, как в TP3. Возможно, понадобится и форма с именем внешней метки для macro11, решим позже.

### 2.5. Операторы

```
compound-statement ::= "begin" statement { ";" statement } "end"
statement          ::= [ label ":" ] ( simple-statement | structured-statement )
simple-statement   ::= assignment | procedure-call | goto-statement | inline-statement | (пусто)
assignment         ::= ( variable | function-identifier ) ":=" expression
procedure-call     ::= procedure-identifier [ "(" actual-param { "," actual-param } ")" ]
actual-param       ::= expression [ ":" expression [ ":" expression ] ]
goto-statement     ::= "goto" label
inline-statement   ::= "inline" "(" code-element { "/" code-element } ")"
code-element       ::= [ "<" | ">" ] code-item { ( "+" | "-" ) code-item }
code-item          ::= unsigned-integer | constant-identifier | variable-identifier
                     | subprogram-identifier | "*"

structured-statement ::= compound-statement | if-statement | case-statement
                     | while-statement | repeat-statement | for-statement | with-statement
if-statement       ::= "if" expression "then" statement [ "else" statement ]
case-statement     ::= "case" expression "of" case-element { ";" case-element } [ ";" ]
                       [ "else" statement { ";" statement } ] "end"
case-element       ::= case-label-list ":" statement
case-label-list    ::= case-label { "," case-label }
case-label         ::= constant [ ".." constant ]
while-statement    ::= "while" expression "do" statement
repeat-statement   ::= "repeat" statement { ";" statement } "until" expression
for-statement      ::= "for" variable-identifier ":=" expression ( "to" | "downto" ) expression "do" statement
with-statement     ::= "with" variable { "," variable } "do" statement
```

- `else` относится к ближайшему `if` без `else` (§7.2.2.1). Перед `else` в `if` точка с запятой недопустима.
- В `case` ветка `else` может содержать несколько операторов через `;` до `end` (прил. I). Это расширение TP3.
- Тип меток `case` совпадает с типом селектора. Селектор — любой простой тип, кроме Real (ошибка 46).
- `inline`: подробности в разделе 10.
- **Параметры с форматом** `x:5`, `r:8:2` допустимы только в `Write`, `WriteLn` и `Str`. Это стандартные идентификаторы, их можно переопределить, поэтому парсер принимает формат у любого параметра, а лишний формат отвергает валидатор.
- `else` внутри ветки `case` относится к `if`, если этот `if` ещё без `else`: `case x of 1: if a then b else c end` — `else c` принадлежит `if`. **[?]** Проверить на эталоне.
- Оператор, начинающийся с идентификатора, различается по следующей лексеме: `:=` — присваивание, `:` — метка, `[` `.` `^` — присваивание элементу, иначе — вызов процедуры. Метка может быть и числом: `10: x := 1`.

### 2.6. Выражения

```
expression         ::= simple-expression [ relational-op simple-expression ]
simple-expression  ::= term { adding-op term }
term               ::= complemented-factor { multiplying-op complemented-factor }
complemented-factor ::= [ "not" ] signed-factor
signed-factor      ::= [ "+" | "-" ] factor
factor             ::= unsigned-constant | variable | function-call | set-constructor
                     | "(" expression ")" | type-identifier "(" expression ")"
unsigned-constant  ::= unsigned-number | string | constant-identifier | "nil"
function-call      ::= function-identifier [ "(" actual-param { "," actual-param } ")" ]
set-constructor    ::= "[" [ set-element { "," set-element } ] "]"
set-element        ::= expression [ ".." expression ]
relational-op      ::= "=" | "<>" | "<" | ">" | "<=" | ">=" | "in"
adding-op          ::= "+" | "-" | "or" | "xor"
multiplying-op     ::= "*" | "/" | "div" | "mod" | "and" | "shl" | "shr"

variable           ::= ( variable-identifier | typed-constant-identifier ) { selector }
selector           ::= "[" expression { "," expression } "]" | "." field-identifier | "^"
```

Особенности TP3 по сравнению со стандартным Pascal:

- **Приоритеты, от высшего к низшему** (§6.1):
  1. унарный минус и плюс;
  2. `not`;
  3. мультипликативные операции;
  4. аддитивные операции;
  5. операции сравнения.
- Знак стоит у множителя, а не у всего выражения. Поэтому допустимы `a * -b` и `a - -b`.
- `not -x` допустимо. `-not x` по грамматике недопустимо **[?]**.
- Операции одного приоритета вычисляются слева направо.
- В грамматике руководства в `expression` повторение сравнений, `a < b < c`. Здесь `relational-op` допускается один раз, как и в тексте главы. **[?]** Проверить на эталоне.
- **Приведение типов**: `ИмяТипа(выражение)` для любого скалярного типа, кроме Real: `Char(78)`, `Integer('7')`, `Day(3)` (§8.3).
- `Mem[адрес]` — переменная-массив байтов (§22.9).

## 3. Типы данных

### 3.1. Стандартные скалярные типы (гл. 3)

| Тип | Значения | Размер в TP3 | Pesto/11 |
|---|---|---|---|
| Integer | -32768..32767 | 2 байта | 2 байта, слово, чётный адрес |
| Byte | 0..255, поддиапазон Integer | 1 байт | 1 байт |
| Boolean | `False < True` | 1 байт | 1 байт |
| Char | 0..255 | 1 байт | 1 байт, КОИ-8Р |
| Real | 1E-38..1E+38, 11 знаков | 6 байт | **[P11]** 4 байта, DEC F, около 7 знаков, чётный адрес |

- Переполнение целой арифметики не обнаруживается. Промежуточные результаты тоже 16-битные (§3.1).
- Byte и Integer смешиваются в выражениях и присваиваниях. Исключение — `var`-параметры (§3.2).
- При переполнении Real программа останавливается с ошибкой. При потере значимости (underflow) результат равен нулю (§3.3).
- Real нельзя использовать в `Pred`/`Succ`, индексах массивов, базе множеств, `for`, `case` и поддиапазонах.

### 3.2. Перечисления и поддиапазоны (гл. 8)

- `Ord` первого значения перечисления равен 0.
- Перечисление, где меньше 256 значений, и поддиапазон с обеими границами в 0..255 занимают 1 байт. Остальные — 2 байта (§22.18.1.1).
- При `{$R+}` присваивание переменной перечисления или поддиапазона проверяет значение на попадание в диапазон. Ошибка выполнения 91.

### 3.3. Строки (гл. 9)

- `string[n]` занимает `n+1` байт. Байт `[0]` хранит текущую длину, символы с индекса 1.
- `S[0]` доступен как Char: `Length(S) = Ord(S[0])`.
- Конкатенация `+` или `Concat`. Результат длиннее 255 — ошибка выполнения 10.
- Сравнение строк: посимвольно по кодам; если одна строка — начало другой, короче та, что меньше. Строки равны только при равной длине и содержимом.
- При присваивании лишние символы отбрасываются.
- Char и строки совместимы. Присваивание строки переменной Char требует длины ровно 1, иначе ошибка выполнения 10.
- При `{$R+}` индекс строки проверяется по **максимальной** длине.
- **[P11]** Сравнения символов и строк идут по кодам КОИ-8Р. Русские буквы в КОИ-8Р упорядочены не по алфавиту; это свойство кодировки, не ошибка.

### 3.4. Массивы (гл. 10)

- Копирование целого массива присваиванием.
- Многомерные массивы хранятся по строкам: быстрее всего меняется правый индекс (§22.18.2.1).
- Массив символов с одним индексом можно использовать в строковых выражениях: он превращается в строку своей длины. Строковую константу той же длины можно присвоить такому массиву. Строковую переменную или выражение — нельзя (§10.3).
- При `{$R+}` индексы проверяются, ошибка выполнения 90.

### 3.5. Записи (гл. 11)

- Поля лежат по порядку. Варианты начинаются с одного адреса, размер записи = фиксированная часть + самый большой вариант.
- `with` открывает поля записи. Запись `with A, B do` равносильна `with A do with B do`.
- **[P11]** Ограничение глубины `with` (директива `W`) не нужно: адрес записи держим во временной ячейке кадра.

### 3.6. Множества (гл. 12)

- До 256 элементов с порядковыми номерами 0..255.
- Хранится сжато: `(Max div 8) - (Min div 8) + 1` байт. Элемент `E` лежит в байте `(E div 8) - (Min div 8)`, бит `E mod 8` (§22.18.1.4).
- На стеке и при передаче по значению множество всегда занимает 32 байта.
- Операции: `+` (объединение), `*` (пересечение), `-` (разность), `=`, `<>`, `<=`/`>=` (включение), `in`.
- `[]` совместимо с любым множеством. `[X..Y]` при `X > Y` пусто.

### 3.7. Указатели и куча (гл. 15)

- Указатель — 2 байта, `nil` = 0.
- Процедуры кучи: `New`, `Dispose`, `Mark`, `Release`, `GetMem`, `FreeMem`, `MaxAvail`, `MemAvail`.
- `New` не принимает вариант записи (прил. D.1).
- `Ord(p)` даёт адрес как Integer, `Ptr(i)` — указатель, совместимый с любым типом указателя (§22.12.2).
- Если адрес больше 32767, `MemAvail` возвращает отрицательное число.
- Совместное использование `Dispose` и `Mark`/`Release` в TP3 имеет ограничения (§15.5). **[?]** Уточнить по главе 15.

### 3.8. Файлы (гл. 14)

Подробности в разделе 6.

### 3.9. Типизированные константы (гл. 13)

- Это инициализированные переменные: их можно менять и передавать как `var`-параметр.
- В определениях других констант и типов их использовать нельзя.
- Структурные константы:
  - массив: `(c1, c2, ...)`, вложенные скобки для многомерных; массив Char можно задать строкой;
  - запись: `(Поле1: c; Поле2: c)`, поля по порядку описания;
  - множество: `[c, c1..c2]`.
- Константы с файлами и указателями недопустимы.
- **[P11]** Типизированные константы попадают в секцию данных с начальными значениями. Обычные переменные TP3 не инициализирует; мы тоже не обнуляем их, если не решим иначе.

### 3.10. Совместимость и присваивание

- Присваивать можно переменной любого типа, кроме файла. Типы должны совпадать; Real := Integer допустимо (§7.1.1).
- Массивы и записи присваиваются целиком только при одинаковом типе.
- **[P11] Выравнивание**:
  - Integer, Real, указатели и все записи и массивы, содержащие слова, размещаются по чётным адресам;
  - внутри записи перед полем-словом может появиться байт-заполнитель;
  - размер элемента массива с такими полями округляется до чётного.

  Поэтому `SizeOf` может отличаться от TP3. Байтовые массивы и строки не выравниваются внутри, но сама переменная начинается с чётного адреса.

| `/` | Integer, Real | **всегда Real** |

| `and` | Boolean / Integer (побитово) | тип операндов |
| `shl` `shr` | Integer | Integer |

| `-` | Integer, Real / множества (разность) | по типам |
| `or` `xor` | Boolean / Integer (побитово) | тип операндов |
| `=` `<>` | скаляры, строки, множества, указатели | Boolean |

- Integer и Real смешиваются, результат Real.
- `shr` — логический сдвиг: `256 shr 7 = 2` (§6.1.3).
- **[?]** Знак результата `div` и `mod` для отрицательных операндов. Ожидается усечение к нулю, знак `mod` по делимому.
- **[?]** Логические выражения вычисляются полностью или сокращённо? В руководстве не описано, предположительно полностью.

## 5. Операторы: семантика

- **`for`** (§7.2.3.1):
  - управляющая переменная, начальное и конечное значения одного простого типа (не Real);
  - если цикл не выполнился ни разу, переменная не меняется;
  - после нормального завершения переменная равна конечному значению;
  - присваивать управляющей переменной в теле нельзя;
  - **[?]** конечное значение вычисляется один раз при входе в цикл.
- **`goto`**:
  - метку нужно объявить в том же блоке;
  - выход из блока (процедуры) запрещён (ошибка 72, прил. D.4);
  - переход внутрь `for` снаружи запрещён (ошибка 71).
- **`case`**: если подходящей метки нет и нет `else`, ничего не выполняется.
- **`Exit`** выходит из текущей подпрограммы, **`Halt`** завершает программу (§16.2.2.9–10).

## 6. Подпрограммы

- Параметры по значению и по ссылке (`var`). Адрес `var`-параметра вычисляется при вызове, включая индексы (§16.1).
- Файлы передаются только как `var` (ошибка 67).
- При `{$V+}` (по умолчанию) длина строки фактического `var`-параметра должна совпадать с формальным. `{$V-}` снимает проверку (§16.1.1).
- Нетипизированный `var`-параметр годится только для `Addr`, `Move`, `FillChar`, `BlockRead`/`BlockWrite` и `absolute` (§16.1.2).
- Функция возвращает скаляр, Real, строку или указатель. Результат задаётся присваиванием имени функции, последнее присваивание определяет значение.
- Процедуры и функции нельзя передавать параметрами (прил. D.7).
- Вложенные подпрограммы видят описания внешних блоков. Пользовательская подпрограмма может перекрыть стандартную.
- **Рекурсия.** В TP3 под CP/M она разрешена только при `{$A-}`, по умолчанию стоит `{$A+}`, без рекурсии. Кроме того, при рекурсии нельзя передавать локальную переменную как `var`-параметр (прил. D.2).
  - **[P11]** Код всегда рекурсивный: кадр через R5, локальные переменные на стеке. Ограничение D.2 снято. `{$A±}` принимается и игнорируется.
- В TP3 есть ограничение: функцию, внутри которой вызываются `Read`/`Write`/`Str`/`Val`, нельзя вызывать внутри `Write`.
  - **[P11]** Стремимся снять это ограничение. Если не получится, задокументировать.

## 8. Текстовый ввод-вывод (§14.5–14.6)

**Устройства**: `CON:` (буферизованный ввод строки с редактированием), `TRM:` (посимвольно с эхом), `KBD:` (без эха), `LST:`, `AUX:`, `USR:`.

**`Eof`/`Eoln`**:
- на диске заглядывают вперёд: `Eoln` истинно, если следующий символ CR или ^Z;
- на логическом устройстве смотрят на последний прочитанный символ.

**`Read`** без файла при `{$B+}` (по умолчанию):
- всегда вводит новую строку с консоли;
- в конец строки добавляется ^Z;
- если значений не хватает: лишние Char получают ^Z, строки — пустые, числа не меняются.

При `{$B-}` `Read` берёт данные из Input по правилам стандартного Pascal.

**Чтение числа**:
- пробелы, табуляции, CR и LF перед числом пропускаются;
- число не длиннее 30 символов и должно заканчиваться пробелом, табуляцией, CR или ^Z;
- ошибка формата — I/O-ошибка 10.

**Чтение строки**: до максимальной длины или до конца строки.

**`ReadLn`** пропускает остаток строки, до CR/LF (на устройстве — до CR).

**Форматы `Write`** (§14.6.3.1):

| Параметр | Вывод |
|---|---|
| `Ch`, `Ch:n` | символ, выравнивание вправо в поле `n` |
| `S`, `S:n` | строка (или массив Char), вправо в поле `n` |
| `B`, `B:n` | `TRUE` или `FALSE` |
| `I`, `I:n` | десятичное число, вправо в поле `n` |
| `R` | плавающий формат, поле 18 символов: ` #.##########E+##`, для отрицательных `-#.##########E+##` |
| `R:n` | плавающий формат в поле `n`, от 1 до 10 цифр после точки; минимум 7 символов (8 для отрицательных) |
| `R:n:m` | фиксированный формат, `m` цифр после точки (0..24); при `m = 0` точки нет; при `m` вне диапазона — плавающий формат |

**[P11]** У DEC F около 7 значащих цифр. Ширину полей сохраняем как в TP3. Как выводить цифры сверх точности (нули или округление) — решим при реализации рантайма.

**`BufLen`** ограничивает длину следующего ввода строки с консоли, по умолчанию 127. После одного `Read` значение возвращается к 127.

**Текстовый файл**: строки разделены CR/LF, конец файла — ^Z (§22.18.2.3.2).

**[P11]** Имена файлов в формате RT-11: `DEV:ИМЯ.ТИП`, имя до 6 символов, тип до 3.

## 9. Директивы (прил. C)

| Директива | По умолчанию в TP3 | Смысл | Pesto/11 |
|---|---|---|---|
| `A±` | A+ | абсолютный (нерекурсивный) код | принимается, игнорируется (код всегда рекурсивный) |
| `B±` | B+ | Input/Output на CON: (B+) или TRM: (B−); действует на всю программу | да |
| `C±` | C+ | Ctrl-C прерывает, Ctrl-S приостанавливает вывод при консольном вводе | позже |
| `I±` | I+ | проверка I/O-ошибок; при I− ошибки проверяются через `IOresult` | да |
| `I имя` | — | включение файла; тип по умолчанию `.PAS`; пробелы в начале игнорируются; если расширения нет, перед `}` нужен пробел | да |
| `R±` | R− | проверка индексов и диапазонов | да |
| `U±` | U− | прерывание программы по Ctrl-C в любой момент | позже |
| `V±` | V+ | строгая проверка длины строк в `var`-параметрах | да |
| `W n` | W2 | глубина вложенности `with` | принимается, игнорируется |
| `X±` | X+ | индексы массивов: скорость или размер кода | принимается, игнорируется |

Неизвестная директива — ошибка 93.

**Включение файлов** (гл. 17):
- **Вложенные include запрещены**: include-файл не может содержать `{$I имя}`. Pesto/11 следует TP3, это ошибка.
- **Директивы, кроме `B` и `C`, действуют до конца файла, в котором стоят.** После возврата из include-файла восстанавливается состояние, которое было до него. `B` и `C` глобальные.
- По TP3 директива `{$I}` должна стоять на отдельной строке. **[P11]** Не проверяется.
- В TP3, если у имени нет расширения из трёх букв, перед `}` нужен пробел, иначе `}` попадёт в имя. **[P11]** Закрывающая скобка в имя никогда не входит.
- Имя файла: пробелы в начале игнорируются, тип по умолчанию `.PAS`. **[P11]** Путь считается относительно включающего файла, регистр букв в имени не важен (DESIGN §2.1).

## 10. Машинный код (§22.15–22.16)

**`inline`**:
- элемент кода — сумма или разность констант, имён переменных, подпрограмм и `*` (текущий адрес);
- в TP3 один байт выдаётся, если элемент состоит только из констант и укладывается в 0..255; иначе выдаётся слово;
- `<` принудительно даёт байт, `>` — слово;
- у переменной берётся адрес (или смещение для локальной).

**[P11]** Команды PDP-11 состоят из слов. Варианты: всегда выдавать слово (а `<` выдаёт байт с последующим `.EVEN`), или сохранить правило TP3 и требовать чётного числа байт. Решим при реализации. Смещение локальной переменной — относительно R5.

**`external адрес`** — подпрограмма в машинных кодах по фиксированному адресу. Соглашение о передаче параметров описано в [DESIGN.md](DESIGN.md), а не берётся из CP/M-версии.

## 12. Сводка отклонений Pesto/11 от TP3

1. Real хранится в 4 байтах DEC F (около 7 знаков); на УКНЦ операции через FIS.
2. Код всегда рекурсивный. `{$A±}` игнорируется, ограничение D.2 снято.
3. Слова выравниваются по чётным адресам, поэтому `SizeOf` записей и массивов может отличаться.
4. Нет `Port`, `Bdos`/`Bios`/`BdosHL`/`BiosHL`, `Chain`/`Execute`, `overlay`, `RecurPtr`, `Aux`/`Usr`.
5. `inline` и `external` работают с машинным кодом PDP-11 и соглашениями Pesto/11.
6. Имена файлов в формате RT-11. Исходник и строки в КОИ-8Р.
7. Нет ограничения на длину строки исходника и глубину `with`.
8. Возможное расширение: `MemW`.

## 13. Проверить на эталонном TP3

- Сокращённое или полное вычисление `and`/`or` для Boolean.
- Знак `div` и `mod` для отрицательных операндов.
- Допустимы ли `-not x` и цепочки сравнений `a < b < c`.
- Вычисляется ли конечное значение `for` один раз; поведение `for` при границах на краю типа (например, `for b := 0 to 255` с Byte).
- Округление в `Round` (половина от нуля?) и в `Write(r:n:m)`.
- Точный вид `Write(r)` и `Write(r:n)` для краевых значений (0, отрицательные, очень большие и маленькие).
- Ограничения на совместное использование `Dispose` с `Mark`/`Release`.
- `Copy`/`Delete` с отрицательным или нулевым `Num`.
- Сравнение массива Char со строкой другой длины.
- Работает ли `UpCase` только с латиницей.
- Boolean со значением не 0 и не 1 (через `absolute`, `Mem`, `Boolean(5)`): результат `not`, сравнений и `Ord`.
- `^X` для небуквенного `X` (`^1`, `^` перед пробелом): какой код получается и какие символы допустимы (§1.5).
