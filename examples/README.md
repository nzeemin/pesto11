Исходники в кодировке КОИ-8Р.

## Игры

Две игры для ДВК и УКНЦ, написанные в конце 1980-х на OMSI Pascal 1 («Паскаль ДВК»). Их исходники восстановлены по исполнимым файлам ([uknc-various](https://github.com/nzeemin/uknc-various): `KINGOM-PASCAL`, `STALK-PASCAL`) и здесь перенесены на диалект Turbo Pascal 3.0 для Pesto/11.

Тексты «Королевства» написаны латиницей в КОИ-7: после символа `#14` (SO) терминал УКНЦ показывает строчные латинские буквы как русские.

## Сборка

```
pesto11 KINGOM.PAS
macro11 KINGOM.MAC -o KINGOM.OBJ -rt11
macro11 PESTO.MAC -o PESTO.OBJ -rt11
pclink11 KINGOM.OBJ PESTO.OBJ -EXECUTE:KINGOM.SAV
```

`KINGOM.SAV` запускается под RT-11 на УКНЦ: `RU KINGOM`. «Сталкер» собирается так же из `STALK.PAS`.

## Что изменено при переносе

Общее для обеих игр:
- восьмеричные константы `33B` стали десятичными;
- строки, разбитые на несколько строк исходника, записаны через `#13#10`;
- `WRITE` строковой константы длиннее 255 символов разбит на несколько: в TP3 строка не длиннее 255.

«Королевство»:
- модули `KINGM2`…`KINGM6` собраны в один файл, объявления `external` убраны;
- `FLOAT(x)` — просто `x`, Integer в Real преобразуется сам;
- псевдоним правителя — `string[10]`, дополненный пробелами до 10 символов, как массив символов OMSI;
- таблица рекордов `KING.DAT` читается и записывается через типизированный файл TP3. В оригинале файл читался и переписывался одновременно через буферы `D^`/`E^` и `GET`/`PUT`.

«Сталкер»:
- ассемблерные вставки `{$C …}` стали `asm … end`;
- `@X` — `Ptr(Addr(X))`, операция `&` — `and`;
- `RANDU` из библиотеки Фортрана заменена на `Random`.

## Ряд Лейбница

π/4 = 1 − 1/3 + 1/5 − 1/7 + … Программа печатает частичную сумму, умноженную на 4, через каждые 1000 членов, а в конце — среднее двух соседних сумм: оно гораздо ближе к π.

Программа написана на общем подмножестве Turbo Pascal 3.0 и OMSI Pascal 1, без правок компилируется обоими. Вывод программ, собранных Pesto/11 и OMSI Pascal, совпадает до цифры (`3.1415000`, среднее `3.1416000`). Тест `0543-prog-leibniz` проверяет вывод в эмуляторе.

## Решето Эратосфена

Классический тест компиляторов Pascal: флаги нечётных чисел 3…16383 (`FLAGS[I]` — число `2·I+3`), 10 проходов, в конце — число простых. Программа общая для Pesto/11 и OMSI Pascal, обе печатают 1899. Тест `0544-prog-sieve` проверяет вывод в эмуляторе.

## QuickSort

Рекурсивная быстрая сортировка Хоара: 1000 чисел от генератора `X := (21·X + 7) mod 1024` (полный период, все числа разные), проверка порядка, первые и последние 10 чисел. Программа общая для Pesto/11 и OMSI Pascal, вывод одинаковый. Тест `0545-prog-qsort` проверяет вывод в эмуляторе.

## LZ77

Программа читает текстовый файл `LZDATA.TXT` (его нужно положить на диск рядом с программой), упаковывает его методом LZ77 (окно 255 байт, совпадения 3–18 байт), распаковывает и сравнивает с исходным текстом. Размер упакованных данных считается в битах: литерал — 9 бит, совпадение — 13. Для `LZDATA.TXT` получается 1494 байта из 2183, 71%.

Исходник общий для Pesto/11 и OMSI Pascal, кроме открытия файла: в TP3 — `ASSIGN(F, 'LZDATA.TXT'); RESET(F)`, в OMSI — `RESET(F, 'LZDATA', 'TXT', V)`. Токены лежат в целочисленных массивах: `Char` у OMSI 7-битный. Тест `0546-prog-lz77` проверяет вывод в эмуляторе.

## TPK

Алгоритм Луиса Трабб Пардо и Дональда Кнута из статьи «The early development of programming languages» (1976): на нём авторы сравнивали ранние языки программирования. Программа вводит 11 чисел, по одному в строке, и в обратном порядке печатает f(t) = √|t| + 5t³ или «TOO LARGE», если значение больше 400. Перенесён с Фортрана (тест `TPK-FORTRANIV` линковщика pclink11). Программа общая для Pesto/11 и OMSI Pascal, вывод одинаковый. Тест `0547-prog-tpk` вводит числа с клавиатуры и проверяет вывод в эмуляторе.

## Множество Мандельброта

Точки −2,3…0,6 по X и −1…1 по Y с шагом 0,1, до 8 итераций; точка печатается символом с кодом `40 − N` (пробел — точка множества). По тесту `2010-mandelbrot` компилятора vibasc. Программа общая для Pesto/11 и OMSI Pascal, картинка одинаковая. Тест `0549-prog-mandel2` проверяет вывод в эмуляторе.

Почти весь код — арифметика Real через стек FIS, поэтому код Pesto/11 здесь ближе всего к OMSI: 89% слов.

## Hunt the Wumpus

Текстовая игра Грегори Йоба (Gregory Yob, 1973), опубликована на BASIC в журнале Creative Computing (1975) и в сборнике «The Best of Creative Computing» (1976). Пещера — додекаэдр: 20 комнат, из каждой три туннеля. В пещере вампус, две бездонные ямы и две комнаты с летучими мышами; рядом с ними игрок слышит предупреждения. Ход — перейти в соседнюю комнату или выстрелить «кривой стрелой» на 1–5 комнат. Попал в вампуса — победа; вошёл к вампусу или в яму, попал стрелой в себя, кончились стрелы — проигрыш.

Перевод с BASIC на Turbo Pascal 3.0 с сохранением правил и текстов:
- `GOSUB`/`GOTO` стали процедурами и циклами, флаг `F` — переменная `STATE`, массив `L` — `LOC`, `S` — типизированная константа `CAVE`;
- `FNA`/`FNB`/`FNC` (`INT(n*RND(0))+1`) — `RANDOM(n) + 1`, в начале `RANDOMIZE`;
- ответ `INPUT I$` — первая буква строки, через `UPCASE`; число вводится строкой и разбирается `VAL`, при ошибке вопрос повторяется (как у `INPUT` в BASIC);
- убрано объявление о программах `WUMP2` и `WUMP3`, которых здесь нет; исправлена опечатка «RAMDOM» в правилах;
- как в оригинале, игра бесконечна: после конца партии — вопрос «SAME SET-UP (Y-N)», выход — `^C^C`.

Для сравнения с OMSI Pascal есть вариант того же алгоритма на диалекте OMSI — `tools/omsi/WUMPUS.PAS` (нет типизированных констант, строк, `Random` и `Exit`; пещеру заполняет процедура, генератор — свой). Код Pesto/11 — 57% слов кода OMSI, образ `.SAV` — 55% байт.

Тест `0548-prog-wumpus` проходит две партии в эмуляторе: невозможный ход, мыши, ошибка ввода числа, отказ «ARROWS AREN'T THAT CROOKED», промах, победа, яма. В тесте вариант программы без `RANDOMIZE` (последовательность случайных чисел известна) и с выходом по ответу не `Y` на «SAME SET-UP».

## Крестики-нолики

Решение задачи «Tic-tac-toe» с Rosetta Code (Pascal), адаптированное к Turbo Pascal 3.0. Человек играет O, компьютер X, начинают по очереди. Компьютер рекурсивно перебирает все продолжения до конца партии; перебор всех партий на модели (Python) подтвердил, что ходы всегда допустимы, а компьютер не проигрывает (выигрывает 498 и сводит вничью 183 партии из всех, когда начинает человек). Победа или ничья объявляются после каждой партии.

Что исправлено при переносе:
- `CheckWinner` читал результат по имени функции (`if CheckWinner = Unassigned`). В TP3 и стандартном Pascal это рекурсивный вызов без конца — результат теперь в локальной переменной;
- при вводе вне 1–9 программа обращалась к `B[I, J]` с индексом −1 или 3 — теперь клетка проверяется только для допустимого номера; ход читается строкой и `Val`, нечисловой ввод не роняет программу;
- `function ...: string` без длины в TP3 нельзя — `PlayGame` возвращает победителя, сообщение печатает главная программа; `Inc`/`Dec` (TP4) заменены на `K := K + 1`;
- бесконечный цикл партий — вопрос «Another game (Y/N)?»; опечатка «Opps» — «Oops».

Первый ответ компьютера, когда начинает человек, — перебор восьми ходов вперёд: на УКНЦ около 80 секунд (у OMSI Pascal — около 7 минут). Дальше ходы быстрые.

Для сравнения с OMSI — вариант `tools/omsi/TICTAC.PAS` (нет строк и `Random`). Тест `0551-prog-tictac` проходит две партии в эмуляторе: ошибки ввода, занятая клетка, победа компьютера, ничья; в тесте нет `Randomize`.

## Размер кода

Эти программы — эталон для сравнения с OMSI Pascal (DESIGN.md §7.11): код программы Pesto/11 занимает около 71% слов кода OMSI, полный образ `.SAV` с рантаймом (без глобальных переменных) — около 66% байт. Все примеры входят в сравнение. Повторить замер: `python tools/codesize.py ПАПКА_uknc-various`.
